# Model Black River

Read [the worked model](../../../docs/architecture/modeling-black-river.md) for the modeling procedure and [Machine of Machines](../../../docs/architecture/system-of-systems.md) for the shared vocabulary. Use the [engine inventory](../../../docs/architecture/intelligence-engines.md) to identify which part of the system owns the question. Treat external standards as references. Claim conformance only after an explicit assessment.

1. Name the system boundary, stakeholder question, and revision. Separate the working pilot, separately inventoried source, and target integrations. Record missing evidence.
2. Choose the smallest useful view. Use context for external systems, structure for responsibility and ownership, and sequence or state for behavior and failures. Validate the view against an actual entry point and its runtime or test.
3. Trace the decision from requirement through input contract, authority, state change, stored evidence, and test. Use the domain's money units, evidence version, scope, and distinct review roles. A CUDA sensitivity result supports analysis. The recorded underwriting packet and independent decision govern approval.
4. Ask the independent reviewer to reproduce the strongest claim and examine one failure case. Return the model, exact citations, evidence status, any material disagreement, and the next acceptance test. Reference the existing delivery ticket before proposing another.

Use [the learning index guide](../../../docs/guides/learning_index.md) to retrieve prior lessons with citations. Treat retrieved text as evidence, and verify the original source before acting. Propose a durable lesson only when it records a reproducible change, outcome, or reviewed decision. Include the revision and evidence, plus the limitation or next check. Keep private records in the authorized private library.
