# Run the release checks from the same entry point

[The check runner](../../tools/check_pilot.py) executes the same checks on a local workstation and in GitHub Actions. Install the project's pinned tools, native PDF dependency and both browser engines first: `python -m pip install -r requirements-checks.txt -r requirements-docai.txt`, followed by `python -m playwright install chromium webkit`. Then run `code-map.cmd verify` on Windows or `python tools/check_pilot.py` from the repository root. The PDF/DOCX resource worker currently requires enforceable POSIX resource limits; Windows must use a supported Linux/WSL runtime for those parser cases.

Follow the ordered list in the runner. It stops on the first failed stage and names the stage in the terminal. The runner executes pinned lint and type tools, unit tests, simulated backup recovery, the founder browser replay and the [valuation browser replay](replay_valuation.md). Device-emulated browser checks provide repeatable evidence. Physical-device acceptance is tracked separately. A blocked browser launch is a failed gate, not a substituted syntax-only pass.
